# QQ 群成员长期记忆：需求与初步设计

## 1. 目标

机器人以 QQ 号识别群成员，归档有限期限内的群文本消息，每日生成一次结构化成员画像，并在该成员触发 AI 时把相关画像作为辅助材料传给模型。

画像只用于调整语气、选材和交流方式，不应每次主动复述，也不能覆盖当前消息或既有人设提示词。

## 2. 功能定位

- 身份主键为 `user_id`，群内画像主键为 `group_id + user_id`。
- 不跨群自动共享画像，避免把一个群的信息泄露到另一个群。
- 该模块不直接回复用户，不改变触发规则，只给正常 AI 回复提供内部材料。
- 成员画像由大模型根据旧画像和当日发言完整归纳，程序只负责校验结构、限制长度和持久化。
- 当前消息和人设提示词始终高于历史画像；模型不应主动说明自己读取了画像。
- 不保存图片、语音和视频原文件；归档文本以及有限的媒体元数据。
- 多媒体消息额外保存类型、文件标识和时长等小型元数据，不保存二进制或Base64。合并转发最多展开3条、每条50个节点，并限制文本总量。
- 图片画面、视频内容和语音正文不会在被动归档时调用模型解析；总结提示中会明确标记为未解析。合并转发中的文本可以参与总结。
- 原始消息按配置到期删除；聚合画像独立保存。
- 正式开放前应告知群成员，并继续补充查看、退出和删除个人记忆的命令。

## 3. 初步实现

### 3.1 磁盘结构

```text
memory_data/
  journal/YYYY-MM-DD/GROUP_ID/USER_ID.jsonl
  interactions/YYYY-MM-DD/GROUP_ID/TARGET_USER_ID.jsonl
  members/GROUP_ID/USER_ID.json
  profiles/GROUP_ID/USER_ID.json
  jobs/YYYY-MM-DD.done
```

每条群消息直接追加到当天、当前成员的 JSONL，不放入常驻消息数组。按成员分片使每日任务可以一次只读取和释放一个人的消息，不会建立包含全群原文的 Map。成员画像使用临时文件加重命名的方式原子更新。每日完成标记用于防止云服务器重启后重复总结。

每条消息还会更新轻量成员目录，保存 QQ 号、当前群名片、QQ 昵称和最近的历史别名。身份仍以 QQ 号为准，昵称只用于解析自然语言中的成员指代。

首版采用 JSONL/JSON，避免云服务器安装原生 SQLite 模块时遇到 Node ABI 或编译依赖问题。`member-memory` 对存储进行了封装，数据量明显增加后可替换成 SQLite，而不改变消息处理和模型调用接口。

### 3.2 消息采集

采集发生在自定义回复、命令和 AI 触发判断之前，因此普通群聊也能被记录。以下内容不记录：

- 私聊消息；
- 机器人自己发送的消息；
- 没有文本的消息；
- 超出 `AI_MEMORY_MESSAGE_MAX_CHARS` 的尾部内容。

首版尚未处理撤回事件；这不影响成员归纳和回复辅助主链路。

### 3.3 每日总结

服务启动时立即检查，之后每五分钟检查一次，在 `AI_MEMORY_SUMMARY_HOUR` 之后总结前一天。读取采用逐行流式处理，但每个成员仍有两层硬限制：

- `AI_MEMORY_DAILY_MAX_MESSAGES`：最多保留的当日消息数；
- `AI_MEMORY_DAILY_MAX_CHARS`：最多保留的当日字符数。

成员逐个调用模型并立即写盘，不会把全群消息同时拼成一个模型请求。只有当天本人发过言的成员才进入成员级总结；但输入不仅包括本人发言，还会从轻量互动索引读取其他成员当天对他的 `@`、引用和定向回复。

画像采用累计迭代结构，而不是每日覆盖：保存 `version`、当前累计画像和最近30天 `dailyHistory`。大模型同时输出当天增量观察和更新后的完整画像；程序做字段级合并，模型漏掉字段时保留旧值，近期事件则去重并按过期时间淘汰。

随后按群执行一次有硬上限的群级总结。输入包含发言者QQ号、消息ID、群头衔、`@`对象、引用作者和消息顺序，用于归纳自然称呼、互动关系、群内角色和群梗。归纳依次使用现有 OpenAI、DeepSeek、Gemini 大模型路径。每个成功成员和群都有独立完成标记；单项失败不会阻断其他任务，重试时也不会再次调用已经成功的项目。

### 3.4 两级辅助加载

AI 被触发时默认只读取当前群、当前 QQ 的 `communicationStyle`，构建一段不超过 500 字的回复风格参考。它只调整措辞方式，不引入兴趣、经历或其他成员概括。

完整画像不再固定注入。Agent 提供一个无参数的 `member_memory` 工具，由大模型根据当前对话判断是否需要调用。适合调用的场景包括用户兴趣、过往信息或长期特点与当前回复确实相关；普通知识问答和无关闲聊不需要调用。

工具只允许读取当前群的当前发言者，返回称呼、长期概括、兴趣、已知信息和不确定推断。没有画像时返回内部的 `available=false`，并明确要求模型直接正常回答；任何“未找到成员画像、没有记忆、缓存为空”等状态都不得出现在用户回复中。

Agent 另提供 `resolve_group_member` 工具。当消息中出现昵称、群名片或历史别名，且身份对应关系会影响回答时，大模型可以在当前群内查询。精确匹配优先；存在多个候选时只返回候选，不允许模型擅自确定。QQ 号仅作内部唯一标识，不要求在正常回复中展示。

模型推断别名和群关系保存原始可信度与最后确认日期。读取时按时间计算有效可信度：长期未再次确认的称呼会逐渐退出候选，群关系低于阈值后不再作为回复材料。近期事件单独保存过期时间，到期后加载画像时自动过滤。

OpenAI Responses、OpenAI Chat Completions、Gemini 和 DeepSeek 回退路径共用动态系统提示词组装，人设原文和当前消息始终优先。

## 4. 内存与磁盘控制

- 原始消息不常驻内存，收到后立即追加磁盘。
- 画像缓存采用 TTL + LRU 数量上限，默认 30 分钟、500 人。
- 消息 ID 去重缓存采用 TTL + 数量上限，默认 1 小时、5000 条。
- 短期会话、图片上下文、角色和拍一拍缓存每五分钟清理，并受 `AI_RUNTIME_CACHE_MAX` 限制。
- 每人每日总结输入默认不超过 300 条、30000 字。
- 原始日志默认保留 14 天，每日任务后清理。
- 图片上下文本身仍可能包含 Base64 或媒体数据，应保持较短 TTL 和合理的 `AI_IMAGE_CONTEXT_MAX`。

## 5. 云服务器部署建议

- 设置系统时区或进程环境变量 `TZ=Asia/Shanghai`。
- 将 `AI_MEMORY_DIR` 放在持久化磁盘，并纳入加密备份策略。
- 不要把 `memory_data/` 提交到 Git。
- 使用单实例运行。当前 JSONL 方案不支持多个机器人进程同时写同一目录。
- 为进程设置合理内存上限，并监控 RSS、日志目录大小、模型调用失败率和每日处理人数。
- 功能默认开启；如需暂停，只设置 `AI_MEMORY_ENABLE=false`。

## 6. 配置基线

```dotenv
TZ=Asia/Shanghai
AI_MEMORY_ENABLE=true
AI_MEMORY_DIR=memory_data
AI_MEMORY_RETENTION_DAYS=14
AI_MEMORY_PROFILE_CACHE_TTL=1800
AI_MEMORY_PROFILE_CACHE_MAX=500
AI_MEMORY_MESSAGE_MAX_CHARS=1000
AI_MEMORY_DAILY_MAX_MESSAGES=300
AI_MEMORY_DAILY_MAX_CHARS=30000
AI_MEMORY_GROUP_DAILY_MAX_MESSAGES=500
AI_MEMORY_GROUP_DAILY_MAX_CHARS=50000
AI_MEMORY_CONTEXT_MAX_CHARS=1200
AI_MEMORY_DEDUPE_TTL=3600
AI_MEMORY_DEDUPE_MAX=5000
AI_MEMORY_SUMMARY_HOUR=4
AI_RUNTIME_CACHE_MAX=1000
```

## 7. 后续迭代

1. 增加按群开关和手动补跑管理命令。
2. 增加撤回同步删除。
3. 将模型归纳配置拆成可选的独立模型。
4. 增加失败退避和运维指标。
5. 数据规模增长后迁移 SQLite，并提供旧 JSONL 导入脚本。
6. 为事实加入证据、可信度、过期时间和冲突合并策略。

## 8. 验收标准

- 普通群聊文本可以按群、日期、QQ 号持久化。
- 进程重启不会丢失已归档消息和画像，也不会重复完成同一天总结。
- 未触发 AI 的普通消息不会进入现有短期上下文 Map。
- 画像缓存超过 TTL 或最大数量后能够释放。
- 单个成员的每日总结输入有明确上限。
- 没有画像时回复行为与当前版本一致。
- 关闭 `AI_MEMORY_ENABLE` 后不创建或读取成员记忆数据。
